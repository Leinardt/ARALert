Capstone Application Title ARALert: A Student Performance Monitoring and Early Academic Risk Detection System for the ARAL Program of Palanas National Agriculture High School
What the application does and who uses it ARALert is a web-based student performance monitoring and early academic risk detection system designed for Palanas National Agriculture High School (PNAHS). The system allows attendance logging through QR code scans for students and faculty, enables tutors to efficiently record weekly student scores, and utilizes data analytics to predict each student’s academic risk level (High Risk, Moderate Risk, Low Risk). Furthermore, the system provides role-based access control (RBAC) to ARAL program tutors, students, faculty, and the school principal, where each distinct user role has a dedicated dashboard to ensure data integrity and facilitate timely academic interventions.

Why this option fits your application
For 1B (First Choice): ARALert is an active web platform utilized daily by tutors, students, and administrators for live QR attendance tracking and weekly assessment scoring. Maintaining high availability and zero downtime during operational school hours is crucial. Option 1B provides complete service lifecycle automation—enabling smooth deployment, daemon process control (start/stop/pause/resume), active status monitoring, safe patching with failure detection and rollback, and a dedicated maintenance mode so users receive clear notices rather than server errors during updates.
For 1A (Second Choice): ARALert manages critical DepEd student records, Phil-IRI reading scores, and attendance histories in PostgreSQL. Option 1A directly ensures data resilience through automated backups, backup verification, rapid disaster recovery (<10 minutes), disk threshold alerts, and health logging to guarantee zero data loss.
Risks you expect and how you will handle them
1. Risk: Broken updates, package conflicts, or failed migrations during patching that disrupt live attendance or scoring.
Handling: The update script performs an automatic pre-deployment database backup, executes post-update health checks, and automatically rolls back to the previous stable Git commit and database state if errors or non-200 responses are detected.
2. Risk: Abrupt daemon termination causing locked PostgreSQL connections, incomplete transactions, or orphaned processes.
Handling: Implement graceful shutdown procedures using SIGTERM signal trapping to complete pending HTTP requests and activate a maintenance mode notice before stopping backend services.
3. Risk: Resource exhaustion (CPU/RAM spikes) during peak concurrent QR scanning periods across multiple classrooms.
Handling: Monitoring and health scripts track system metrics continuously, logging performance summaries and issuing automated threshold warnings before service degradation occurs.
